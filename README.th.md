# money — «the toll before the strategy»

> **ไม่มีกลยุทธ์ใดไปถึง production ได้โดยไม่ผ่านประตู (การคัดเลือก):** ค่าคาดหวังสุทธิเป็นบวก
> **นอกตัวอย่าง (out of sample)** ที่ **ต้นทุนจริง** ของบัญชีที่จะรันมัน
> ประตูไม่ใช่แนวทางปฏิบัติ: มันคือโค้ด และการปฏิเสธของมันผูกพัน

ภายใต้ชื่อ *denaro* มีโค้ดเบส **สี่** ชุดที่สืบทอดต่อกัน — `C:\dev\denaro` (Binance,
มือถือ), `money` ตัวก่อนหน้า (grid, DCA, scalper, hedge, futures, sentiment),
`alpha-omega-trading` (49,162 บรรทัด, 17 บอต, สามเครื่อง) และ `~/denaro2` บน VPS — และ
**ไม่มีสักชุดที่ทำเงินได้แม้แต่ยูโรเดียว** ไม่ใช่เพราะบั๊ก: เพราะระบบถูกสร้าง *ก่อน*
แล้วค่อยมองหาสิ่งที่พอจะจับได้ *ทีหลัง* ที่นี่ลำดับกลับกัน และโค้ดชุดก่อนหน้า
อาศัยอยู่ใน `legacy/` ถูก track พร้อมประวัติของมัน เป็นความทรงจำถึงสิ่งที่เคยลอง — ไม่ใช่
รากฐานให้สร้างต่อ

## 🚦 ประตู (การคัดเลือก) — 8 เกณฑ์, 3 คำตัดสิน

ทั้งแปดข้อต้องผ่าน คำตัดสินมีสามแบบ และ "ข้อมูลไม่เพียงพอ" เป็นคำตัดสินจริง ไม่ใช่
ข้ออ้าง

| # | เกณฑ์ | เกณฑ์ผ่าน |
| :--- | :--- | :--- |
| 1 | ขนาดตัวอย่าง | `>= 30` operations, ไม่เช่นนั้น **ข้อมูลไม่เพียงพอ** |
| 2 | ค่าคาดหวัง | bootstrap CI ที่ 90%, ขอบล่าง `> 0`, seed คงที่ |
| 3 | t-statistic | `> 1.65` (one tail, 5%) — รายงานเสมอ แม้ตอนที่มันไม่ผ่าน |
| 4 | Profit factor | `> 1.20` |
| 5 | Drawdown | `<= 25%` ของทุน |
| 6 | **ค่าธรรมเนียมถูกคุ้ม** | ค่าคาดหวังสุทธิ `>= 3x` ของต้นทุนไป-กลับตามอัตราที่สมมติไว้ |
| 7 | นัยสำคัญทางเศรษฐกิจ | `>= 10 EUR/year` ที่คาดไว้ บนทุนอ้างอิง 1000 EUR |
| 8 | ความเป็นอิสระของ block | การตัด block ที่ดีที่สุดออกต้องไม่ทำให้ค่าคาดหวังกลายเป็นลบ |

เกณฑ์ข้อ 6 คือข้อที่โปรเจกต์ก่อนหน้าไม่เคยมี เกณฑ์ข้อ 8 มีอยู่เพราะโปรเจกต์ก่อนหน้า
มี **ผลตอบแทนทั้งหมดอยู่ใน block เดียวจากสาม block** และไม่มีใครสังเกตเห็น

อัตราค่าธรรมเนียมไม่ใช่สมมติฐานอีกต่อไป: มันถูกอ่านจากบัญชี

## 📉 สามคำตัดสิน — สิ่งที่ประตูเก็บเข้าคลัง และเพราะอะไร

| node | คำตัดสิน | ตัวเลขที่ตัดสินมัน |
| :--- | :--- | :--- |
| A — trend ระยะยาว | **เก็บเข้าคลัง** | in-sample `+1.96%/op`, **out-of-sample `-1.21%/op`** (t `-0.44`); มีเพียง 2 จาก 9 หน้าต่างสั้นที่เป็นบวก และ **0 หน้าต่างที่มี >= 5 operations** |
| B — grid แบบปรับตัว | **เก็บเข้าคลัง** | **1581 operations**, สุทธิ `-1.18%/op`, **t `-8.54`**, PF `0.569` |
| C — momentum 4h | **เก็บเข้าคลัง** | 4h สุทธิ `-0.36%/op`, 1d สุทธิ `-1.67%/op`; คันโยกด้านต้นทุนมองเห็นได้ (coverage `-0.654` → `1.716`, EUR/year `-208` → `+69.61`) และ **ก็ยังไม่พอ** |

สามข้อค้นพบที่อยู่ยืนยาวกว่าคำตัดสิน:

1. **สำหรับ trend ค่าธรรมเนียมไม่เกี่ยวเลย** นอกตัวอย่าง edge เปลี่ยนเครื่องหมาย; การเปิด
   X-Perps มีค่า **0.94 EUR/year** บน edge นั้น ไม่มีส่วนลดคอมมิชชันใดสร้าง edge ได้
2. **grid มีข้อบกพร่องเชิงโครงสร้าง ไม่ใช่เชิงปรับจูน** การกวาดด้วยช่องว่างคงที่เป็นลบตั้งแต่
   `0.10%` ถึง `7.00%`; จุดคุ้มทุน **ไม่ถูกไปถึงแม้ที่ 12.7x ของค่าธรรมเนียม** และ 98.672% ของ
   operations มีช่องว่าง *สูงกว่า* ค่าธรรมเนียม (4.4x–8.6x) ขณะที่ยังขาดทุน 1.18% ต่อ operation
   เหตุผล: +1 cycle ได้ `s` แต่ −1 band break เทขาย inventory ที่ราคาตลาดและคิดต้นทุน
   ราว `3s` การวินิจฉัยของโปรเจกต์ก่อนหน้า ("ช่องว่างต่ำกว่าค่าธรรมเนียม") นั้น **ถูกแต่ว่า
   ไม่ครบถ้วน**: การเพิ่มมันอย่างเดียวไม่พอ
3. **คันโยกด้านต้นทุนมีจริงและตอนนี้วัดได้แล้ว และมันไม่เลื่อนอะไรขึ้นเลย** บน 4H มี 1 เกณฑ์
   จาก 8 ที่พลิก (economic relevance) และคำตัดสินไม่ขยับ

1. **ห้ามมี execution ก่อนมี edge ที่ถูกเลื่อนขึ้น** โปรเจกต์ก่อนหน้ามี 17 บอตและศูนย์
   เทรดที่ตรวจสอบยืนยันได้
2. **ห้ามอ้างผลการดำเนินงานโดยไม่กระทบยอด** กับยอดคงเหลือและคำสั่งจริง
3. **ห้ามตั้งทุนที่ไม่ตรงกับที่บัญชีมี** node ที่ไม่มีเงินต้องพูดว่า
   `NON FINANZIATO` ไม่ใช่ข้าม tick ไปเงียบ ๆ (tick หายไป 1,486 ครั้งโดยไม่มีสัญญาณเตือนแม้แต่ครั้งเดียว)
4. **ห้ามสั่งโดยไม่มี idempotency key** การแครชระหว่างส่งกับบันทึกทิ้งเงินที่ commit ไปแล้ว
   ซึ่งบอตมองไม่เห็น
5. **ห้าม telemetry ที่อ่านแล้วเหมือนซากฟอสซิล** ไฟล์เก่าไม่ใช่บอตที่กำลังรัน
6. **ห้ามมี LLM ใน hot path** ในโหมด shadow ได้ แต่ห้ามตัดสิน
7. **ห้าม path ลอยไปมา**: systemd และ cron ใส่เวอร์ชันใต้ `deploy/` พร้อม
   `PROJECT_ROOT` แบบพารามิเตอร์ มันก่อ outage 10 จาก 12 ครั้ง
8. **ห้ามลดเกณฑ์ลงเพื่อให้อะไรบางอย่างผ่าน** ถ้าประตูเก็บเข้าคลัง มันก็ถูกเก็บเข้าคลัง

## 🚧 งานที่เปิดอยู่ เรียงตามมูลค่า

1. **การตัดสินใจของเจ้าของ — การประเมิน X-Perps** `acctLv` 1 → 2 มันคือคันโยกที่ใหญ่ที่สุดที่โปรเจกต์
   มี, มันมีค่า 7.86x บนค่าธรรมเนียม, และมันไม่ใช่โค้ด บน EEA มันอาจขึ้นกับ MiCA: ต้อง
   ตรวจสอบกับ OKX
2. **การตัดสินใจของเจ้าของ — 26 EUR ไปไหน** บัญชีหลักไม่ใช่ node: สถาปัตยกรรมคือ
   หนึ่ง node = หนึ่งตระกูล = หนึ่ง subaccount เฉพาะ
3. **การตัดสินใจของเจ้าของ — 1000 EUR** ที่ 26 EUR เกณฑ์ความมีนัยสำคัญของประตูเรียกหา 38.5% สุทธิ
   ต่อปี; ที่ 1000 EUR มันเรียกหา 1.0% ทุนไม่ได้สร้าง edge: มันทำให้กำไร
   มองเห็นได้
4. **แท่นทดสอบแบบไม่ส่งคำสั่งจริง** (สเปกใน `docs/02`): อ่านยอดคงเหลือจริง, ใช้การ์ดกัน
   `NON FINANZIATO`, คำนวณคำสั่ง และ **ไม่ส่งอะไรเลย** การ implement อยู่ใน `deploy/`
5. **คำถามข้อที่สี่ ไม่ใช่กลยุทธ์ตัวที่สี่** เมื่อสามตระกูลถูกเก็บเข้าคลัง คำถาม
   ไม่ใช่ "กลยุทธ์อะไรต่อไป" อีกแล้ว แต่เป็น **อะไรทำให้ edge ถูกค้นพบได้** ภายใต้ค่าธรรมเนียมนี้ บน
   ตลาดเหล่านี้ ด้วยทุนนี้
